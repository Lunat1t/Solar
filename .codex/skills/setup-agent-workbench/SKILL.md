# Agent Workbench

Определи доступную папку проекта. Не предполагай, что удалённая машина подключена. Объясняй значимые этапы простым языком.

## Настройка

1. Прочитай инструкции проекта, манифесты и тесты. Сохрани чужие изменения.
2. Выполни `python3 <skill-dir>/assets/workbench/agent_workbench.py --root <проект> init`.
3. Проверь `.agent-workbench/config.json`: команды должны соответствовать проекту, завершаться и проверять реальные требования. При необходимости адаптируй их. Зависимости устанавливай по принятому в проекте lockfile в пределах разрешённой работы.
4. Выполни `status` и `check`. Пустые проверки не означают успешной верификации.
5. Объясни требование доверенного Git-проекта и просмотра хуков через `/hooks`. Не обходи доверие и не заявляй об активации только по наличию файлов. Читай [runtime.md](references/runtime.md) при настройке хуков.
6. Для необязательного Git hook используй `git-hook`. Сохрани существующий менеджер хуков. Читай [workflow.md](references/workflow.md) при настройке рабочего процесса.

## Работа

Создай контракт через `task --goal '...' --accept '...' --scope 'package/**'`. Загружай нужную инструкцию из `.agent-workbench/roles/` по необходимости.

Для интерактивной работы используй текущий runtime. Для локального автоматического цикла используй `run`, когда Codex CLI, вход и доверие хукам реально доступны.

Воспроизводи ошибки до исправления. Обновляй checkpoint длинной работы. Проверяй изменения осмысленными командами. Разделяй прохождение проверок, доказательства критериев и решение по ревью. `awaiting_review` требует разбора результатов; это не автоматическое одобрение.

Для независимых исполнителей используй отдельные worktrees. Делегируй только если это допускают запрос пользователя и инструкции runtime. Передавай задачу и исходные артефакты, не навязывай диагноз. Не создавай постоянную команду только из-за наличия ролей.

Для исследований читай [research.md](references/research.md) и контролируй влияние skills/hooks/memory на baseline.

## Ресурсы

- `assets/workbench/agent_workbench.py`: самостоятельный установщик, задачи, проверки, hooks, runner, worktrees и pre-commit. Python 3.11+, Linux/macOS.
- `scripts/verify_workbench.py`: тесты инструмента без модели и внешних Python-пакетов.
- [workflow.md](references/workflow.md): рабочий цикл и перенос.
- [runtime.md](references/runtime.md): нативные хуки и ограничения.
- [research.md](references/research.md): чистота экспериментов.
