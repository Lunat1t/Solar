# Runtime и хуки

Актуальная документация: https://learn.chatgpt.com/docs/hooks и https://learn.chatgpt.com/docs/non-interactive-mode . Возможности проверялись 5 октября 2026 года; при расхождениях сверяй текущую официальную документацию.

Определения находятся в `.codex/hooks.json`. Хуки из разных слоёв конфигурации объединяются. Нужны доверенный Git-проект и просмотр точных определений через `/hooks`; не подделывай доверие.

`SessionStart` и `UserPromptSubmit` напоминают активную задачу. `PostToolUse` учитывает структурированный exit_code и после второго одинакового сбоя рекомендует диагностику. Состояние сохраняет хеш команды, а не её текст, вывод или пользовательский запрос.

`Stop` возвращает decision=block с причиной для одного дополнительного прохода, если нет актуальных проверок. Здесь block означает продолжение работы. stop_hook_active предотвращает повторную петлю.

Сигналов неизвестного формата не интерпретируй как достоверный сбой. Эти хуки направляют работу, но не заменяют sandbox.

Runner использует `codex exec --json --sandbox workspace-write -o FILE -`, затем отдельный процесс ревью с `read-only`. Он ограничивает время и повторы, но не токены/доллары. Для воспроизводимого исследования фиксируй модель вместо runtime default.

Файлы определения не доказывают активацию. Живой запуск CLI требует установленного Codex и входа в аккаунт.
