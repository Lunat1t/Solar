# Рабочий процесс

Инициализируй существующую папку. Проект без Git может использовать задачи и проверки; нативным хукам и CLI-оркестрации нужен Git.

Установщик добавляет собственный отмеченный блок в AGENTS.md и группы hooks, сохраняя существующие. Конфликты другой версии инструмента требуют ручного разбора.

Автоопределение проверок — предложение. Сверь команды с манифестами проекта. Watch mode замени конечной командой; убедись, что тесты действительно обнаруживаются. Команды хранятся массивами argv без shell interpolation.

Отсутствующая команда даёт exit 127. Пустой набор проверок считается отсутствием верификации. Правка файлов или конфигурации делает прошлые результаты устаревшими.

Рабочий цикл: задача → воспроизведение → реализация → проверки → независимое ревью → доказательства критериев. Runner останавливается на awaiting_review. После разбора используй finish с одним evidence на каждый критерий. Команда фиксирует доказательства, но не определяет истинность текста самостоятельно.

Checkpoint содержит цель, текущую гипотезу, изменённые файлы, результаты проверок, препятствия и следующий шаг. Не записывай секреты. Сырые CLI-логи могут содержать чувствительный вывод: просмотри их перед передачей.

Одна активная задача на checkout. Для независимых исполнителей создавай worktrees. Незакоммиченные правки туда автоматически не переносятся.

Pre-commit проверяет рабочую папку, а не отдельный staged snapshot. При частичном staging отдельно проверь будущий commit. В CI используй ту же check-команду после подготовки окружения проекта.

Для отключения выключи собственные группы в /hooks. При удалении сохраняй чужие файлы и инструкции, убирай только собственный блок и собственные определения.
