# Архитектура Solar

## Три разных уровня

**Модель** генерирует решения. **Harness Codex** выполняет её агентный цикл и предоставляет инструменты. **Solar** добавляет переносимые рабочие соглашения, проверки, состояние задачи и реакции на события.

Solar не реализует собственную LLM и не заменяет sandbox Codex.

## Нативные агенты и режимы

`.agent-workbench/roles/*.md` содержат инструкции режимов работы. Они не создают агентов.

`.codex/agents/*.toml` содержат официальные конфигурации будущих сессий Codex: explorer, worker, verifier и reviewer. Профили наследуют модель из среды. Sandbox, заданный профилем, требует проверки эффективных настроек: live overrides родительской сессии могут влиять на детей.

`run` — простой runner последовательных CLI-процессов. `run-native` — запуск координатора, которому поручено создать нативные subagent-сессии. Python не обеспечивает принудительный spawn; реальное выполнение проверяется по runtime events и `/agent`.

Применяется [локальный стандарт разработки](СТАНДАРТ.md). Его критерии приёмки разделены на машинные проверки и требования к разбору артефактов.

## Рабочий цикл

1. Контракт задачи фиксирует цель, критерии и область изменений.
2. Исполнитель читает проект, воспроизводит проблему и меняет код.
3. Проверки запускают команды из config, сохраняют результаты и состояние файлов.
4. При провале допускается ограниченное количество исправлений.
5. После успешных проверок отдельный Codex-процесс с sandbox `read-only` ищет конкретные ошибки.
6. Цикл заканчивается на `awaiting_review`: требуется разобрать ревью и подтвердить критерии.
7. `finish` сохраняет переданные доказательства и завершает задачу.

## Hooks и auto steering

`SessionStart` и `UserPromptSubmit` добавляют краткое напоминание активной задачи.

`PostToolUse` распознаёт сбой по структурированному `exit_code`. Второй одинаковый провал вызывает рекомендацию пересмотреть причину. Если формат неизвестен, сбой не выдумывается.

`Stop` может запросить один дополнительный проход, если проверки отсутствуют, провалены или устарели. Дальше сообщает о препятствии. Это ограниченная реакция, а не бесконечная автономность.

Определения находятся в `.codex/hooks.json`. Для их исполнения требуются доверенный проект и просмотр точных определений через `/hooks`. Solar не обходит доверие.

## Изоляция и журнал

У каждого checkout одна активная задача. Для параллельной работы — отдельные worktrees. Созданное дерево содержит закоммиченное состояние, не незакоммиченные правки исходной папки.

Журнал хранит stdout/stderr проверок, exit code, время, CLI events и ревью. Эти файлы исключены из Git. Перед передачей логов другим людям проверь их содержимое.

## Контролируемые ограничения

- Scope — инструкция агенту; он не является обязательным контролем файловых прав.
- Успешные проверки не доказывают отсутствие всех ошибок.
- Успешный процесс ревью не означает одобрение.
- `finish` фиксирует текст доказательств, но не проверяет его истинность самостоятельно.
- Время и повторы ограничены; жёсткой отсечки токенов и долларов нет.
- `research_mode` отключает только steering Solar. Остальные навыки, память и хуки среды необходимо контролировать отдельно.
- CI проверяет инструмент и поставку; он не проверяет доступность аккаунта или качество живой модели.

|---|---|
| `agent_workbench.py` | Launcher для полного клона Solar |
