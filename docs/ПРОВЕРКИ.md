# Проверки и CI

## Основная команда

```bash
python3 agent_workbench.py check
```

Команда запускает два вида проверок:

1. 20 тестов инструмента: сохранение настроек, отсутствие проверок, сбои, недоступные команды, устаревшие результаты, изменения во время проверки, ограничение steering, завершение задачи, research mode, таймаут и оркестрация с тестовой заменой CLI.
2. Согласованность поставки: одинаковые каноническая и установленная реализации, наличие checks, hooks, ролей и документов.

Для тестов не нужны внешние Python-пакеты, аккаунт модели или API-ключ. Они работают во временных локальных проектах.

## Актуальность результатов

Каждая проверка связана с задачей, конфигурацией и отпечатком файлов проекта. Правка после проверки делает результат устаревшим. Если сама проверка изменила учитываемые файлы, успешная верификация не записывается.

Генерируемые папки вроде `node_modules`, `dist`, `target`, кеши и внутреннее состояние Workbench исключены из отпечатка. Не размещай учитываемый исходный код в этих папках.

## CI

GitHub Actions запускает ту же команду на Ubuntu и macOS с Python 3.11 и 3.13. Исполнение ограничено временем, права workflow — чтение содержимого. CI не запускает модель.

В чужом проекте используй его собственный CI и подготовку окружения. Установщик не заменяет существующие пайплайны.

## Проверка перед commit

```bash
python3 agent_workbench.py git-hook
```

Если существующий pre-commit отличается, инструмент оставляет его и просит встроить команду проверки в текущую систему. Проверяется рабочая папка; при частичном staging отдельно проверь будущий commit.

## Что пока требует живой среды

Нативные хуки: просмотр и доверие в Codex.

Оркестрация с моделью: установленный Codex CLI, вход в аккаунт, соединение и доступная модель. Автотест использует замену процесса CLI, чтобы проверить управление стадиями без обращения к модели.
