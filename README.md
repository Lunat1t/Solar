# Solar

Конфигурация разработки поверх harness **Codex**: **Agent Workbench**, правила проекта, задачи, проверки, хуки, ограниченный auto steering, оркестрация и независимое ревью.

Solar можно использовать как рабочий проект или как источник сэтапа для другого репозитория. Требуются **Python 3.11+ и Git**, Linux/macOS. Для автоматического исполнения задач дополнительно нужен **Codex CLI** с настроенным входом.

## Быстрый запуск

```bash
git clone https://github.com/Lunat1t/Solar.git
cd Solar
python3 agent_workbench.py status
python3 agent_workbench.py check
```

Проверки не вызывают модель и не требуют API-ключа. После начала работы в Codex просмотри определения в `/hooks` и доверь нужные хуки. Файлы хуков сами по себе не подтверждают их активацию.

## Что включено

| Часть | Назначение |
|---|---|
| Проектный skill | Инструкция по настройке и применению сэтапа |
| `AGENTS.md` | Правила работы в проекте |
| Пять режимов | Markdown-инструкции; сами по себе не создают агентов |
| Нативные агенты | Четыре профиля `.codex/agents/*.toml`; отдельные сессии создаёт Codex |
| Стандарт | Definition of Ready/Done, передача задач и проверка результата |
| Контракт задачи | Цель, критерии готовности и границы изменений |
| Оркестратор | Исполнитель → проверки → ограниченные исправления → ревью |
| Нативные hooks | Напоминание задачи и реакции на события Codex |
| Auto steering | Диагностика повторных сбоев и проверка перед завершением |
| Журнал и checkpoint | Результаты команд и состояние длинной работы |
| Worktrees | Раздельные рабочие папки независимых исполнителей |
| Git hook и CI | Проверка перед commit и в GitHub Actions |

## Перенос в другой проект

Из клона Solar:

```bash
python3 agent_workbench.py --root /absolute/path/to/project init
```

Инструмент добавит рабочие файлы, сохранив существующие инструкции и группы хуков. Затем проверь команды в `.agent-workbench/config.json` целевого проекта и его зависимости.

Для автономного использования копируй файл **`.codex/skills/setup-agent-workbench/assets/workbench/agent_workbench.py`**. Корневой `agent_workbench.py` — launcher, которому нужен полный клон Solar.

## Пример задачи

```bash
python3 agent_workbench.py task \
  --goal 'Исправить расчёт итоговой суммы' \
  --accept 'Пустой список даёт 0' \
  --scope 'src/**' \
  --scope 'tests/**'
```

Можно работать интерактивно с агентом. Для автоматического цикла через локальный Codex:

```bash
python3 agent_workbench.py run
```

После успешных проверок цикл останавливается в состоянии `awaiting_review`. Прочитай ревью и проверь критерии задачи. Завершение процесса ревьюера не означает одобрения кода.

## Нативные агенты и стандарт

Harness — сам Codex: модель, агентный цикл, инструменты, контекст, sandbox и subagent lifecycle. Solar настраивает его для проекта. Markdown-роли — инструкции, TOML-профили — конфигурация агентов, а реальный агент существует после создания отдельной сессии runtime.

Для запроса нативного цикла:

```bash
python3 agent_workbench.py run-native
```

Координатор получает просьбу создать `solar_explorer`, `solar_worker`, `solar_verifier`, `solar_reviewer`. Факт запуска нужно проверить в `/agent` и событиях сессии. Успех команды не доказывает, что каждый subagent был создан. `run` остаётся простым последовательным runner двух отдельных CLI-процессов.

Стандарт проекта находится в [docs/СТАНДАРТ.md](docs/СТАНДАРТ.md). Это явный локальный инженерный стандарт, не заявление о сертификации.

## Статус проверки

20 автоматических тестов инструмента и проверка согласованности поставки. Оркестратор проверен с тестовой заменой CLI. Распознавание профилей и реальный spawn нативных агентов, живой запуск модели и активация нативных хуков в среде пользователя требуют установленного Codex и доверенных определений хуков.

Лимиты времени и повторов реализованы. Жёстких лимитов токенов и стоимости в версии 1.0 нет. Границы файлов задаются инструкцией и не заменяют sandbox.
