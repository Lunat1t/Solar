# Правила работы в Solar

Solar — переносимый инструментарий разработки, а не экспериментальный движок Amnesia.

- Сохраняй совместимость Python 3.11+, Linux/macOS и отсутствие сторонних Python-зависимостей.
- Канонический исходник: `.codex/skills/setup-agent-workbench/assets/workbench/agent_workbench.py`.
- После изменения исходника синхронизируй `.agent-workbench/agent_workbench.py`. Корневой launcher не содержит копию реализации.
- Основная команда проверки: `python3 agent_workbench.py check`.
- Документацию, примеры и сообщения для пользователя оформляй на русском. Названия API и CLI сохраняй как есть.
- Не заявляй, что нативные хуки активны, пока это не подтверждено в runtime.
- Не считай успех процесса ревьюера одобрением кода.

## Agent Workbench

Применяй `docs/СТАНДАРТ.md`: Definition of Ready/Done и контракт передачи работы.
При явно запрошенной многоагентной работе используй нативные профили solar_explorer, solar_worker, solar_verifier и solar_reviewer. Создавай отдельные сессии через инструменты runtime, не переключай только персону основного агента. Сообщай о недоступности spawn.
Не выдавай наличие профиля за факт запуска. Фактические sandbox-права проверяй в текущем runtime: live overrides родителя могут влиять на дочерние сессии.

Читай `.agent-workbench/task.json`: цель, критерии результата и разрешённые границы изменений.
Читай `.agent-workbench/config.json`: реальные команды проверок. Загружай инструкции режима работы по необходимости.
После значимых изменений и перед завершением выполняй `python3 agent_workbench.py check`.
Успех проверок доказывает прохождение этих проверок; остальные критерии требуют собственных доказательств.
Перед исправлением воспроизведи ошибку. После двух одинаковых провалов пересмотри гипотезу причины.
Сохраняй план и следующий шаг длинной работы в `.agent-workbench/checkpoint.md`.
Для независимых исполнителей используй отдельные worktrees. Делегирование зависит от разрешений текущего runtime.
Перед завершением предъяви доказательства критериев задачи и разбери конкретные замечания ревью.
При исследованиях фиксируй baseline, модель и бюджеты. Помощь разработки должна оставаться вне измеряемых агентов.
